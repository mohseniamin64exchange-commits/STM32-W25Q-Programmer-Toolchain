# راهنمای تحویل و ادامه پروژه

## هدف این سند

اگر ویندوز عوض شد، گفت‌وگو پاک شد یا توسعه‌دهنده/هوش مصنوعی دیگری پروژه را ادامه داد، این فایل باید نقطه شروع باشد.

## شرح یک‌خطی پروژه

ساخت دو نرم‌افزار ویندوزی و یک کتابخانه STM32 برای تبدیل منابع چندرسانه‌ای، بسته‌بندی آن‌ها در W25Q، تولید خودکار API/شناسه‌ها و پروگرام یکپارچه Firmware و حافظه خارجی.

## وضعیت کنونی

پروژه در مرحله طراحی معماری و ثبت تصمیم‌هاست. هنوز زبان برنامه‌نویسی رابط ویندوز، فرمت باینری دقیق، پروتکل انتقال، شماتیک پروگرام مشترک و کد اجرایی نهایی انتخاب/پیاده‌سازی نشده‌اند.

## تصمیم‌های قطعی تا امروز

1. دو نرم‌افزار مستقل ساخته می‌شود: Media Converter و Asset Builder.
2. تصویر به RGB565 تبدیل می‌شود.
3. صوت به PCM یا IMA-ADPCM تبدیل می‌شود، نه RGB565.
4. فونت TTF/OTF به Bitmap Font و جدول Glyph تبدیل می‌شود.
5. شناسه هر منبع بعد از ایجاد ثابت می‌ماند و مرتب‌سازی نباید آن را تغییر دهد.
6. خروجی Firmware و منابع جدا هستند: `firmware.hex` و `assets.bin`.
7. یک Container با پسوند اختصاصی مانند `.w25pack` می‌تواند تجربه تک‌فایلی ارائه دهد.
8. سمت STM32 یک کتابخانه آماده آدرس‌دهی، جست‌وجو، نمایش تصویر، پخش صوت و رسم متن را انجام می‌دهد.
9. W25Q از دو مسیر قابل پروگرام است: STM32 واسط یا CH341A مستقیم.
10. هر دو مسیر بهتر است پشتیبانی شوند؛ کاربردشان متفاوت است.
11. صحت داده با CRC32 کنترل می‌شود.
12. به‌روزرسانی آینده باید بتواند فقط سکتورها/منابع تغییرکرده را بنویسد.

## فرض‌های فعلی، نه تصمیم نهایی

- MCU مرجع: STM32F103VET6 با Flash داخلی ۵۱۲ کیلوبایت
- External Flash مرجع: W25Q16، ظرفیت ۲ مگابایت
- Image: RGB565 خام یا RLE
- Audio: Mono، نرخ ۸ یا ۱۶ کیلوهرتز، PCM8 یا IMA-ADPCM
- انتقال از PC به STM32: ابتدا UART برای نمونه‌سازی، سپس USB CDC
- بافر دوگانه ۲ یا ۴ کیلوبایتی برای هم‌پوشانی دریافت و نوشتن

## مواردی که نباید اشتباه تفسیر شوند

- «STM32 هیچ نقشی ندارد» یعنی تبدیل و طراحی منابع را انجام نمی‌دهد؛ در زمان اجرا همچنان باید از W25Q بخواند و خروجی را به LCD/DAC/PWM بدهد.
- `.w25pack` یک بسته نگهدارنده است، نه یک تصویر حافظه واحد برای دو تراشه.
- فایل HEX میکرو و BIN حافظه خارجی نباید کورکورانه با هم Merge شوند.
- CH341A هنگام اتصال روی برد نیازمند مهار STM32 و کنترل ولتاژ/تداخل باس است.

## ترتیب پیشنهادی شروع مجدد

1. README و DECISIONS را بخوانید.
2. مدل دقیق LCD، مسیر صوت، نوع W25Q و برد STM32 را قطعی کنید.
3. فرمت `assets.bin` و Manifest را نسخه‌بندی کنید.
4. یک PoC با یک تصویر، یک صدا و یک فونت بسازید.
5. درایور W25Q و API خواندن منبع را روی برد تست کنید.
6. سپس UI نرم‌افزارها و پروگرام یک‌دکمه‌ای را توسعه دهید.

## معیار موفقیت نسخه اول

- واردکردن یک PNG و تولید RGB565 صحیح
- واردکردن WAV/MP3 و تولید صوت قابل پخش
- تولید فونت Bitmap برای بازه مشخص حروف فارسی/لاتین
- ساخت `assets.bin` و `asset_ids.h`
- نوشتن و Verify روی W25Q16
- نمایش تصویر، پخش صوت و رسم متن از طریق شناسه ثابت
- پروگرام Firmware و Assets با گزارش شفاف خطا و پیشرفت
