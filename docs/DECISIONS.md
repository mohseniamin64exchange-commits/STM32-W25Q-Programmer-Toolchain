# دفتر تصمیم‌های معماری

## D-001: جداسازی Converter از Builder

**وضعیت:** پذیرفته‌شده

Converter مسئول تبدیل رسانه است؛ Builder مسئول سازمان‌دهی، آدرس‌دهی، بسته‌بندی و تولید کد. این جداسازی امکان استفاده مستقل از فایل‌های تبدیل‌شده و توسعه ساده‌تر را فراهم می‌کند.

## D-002: فرمت منابع تصویری و صوتی

**وضعیت:** پذیرفته‌شده

- تصویر: RGB565؛ فشرده‌سازی RLE گزینه قابل بررسی است.
- صوت: PCM یا IMA-ADPCM؛ انتخاب نهایی براساس کیفیت، حجم و توان پردازشی انجام می‌شود.
- فونت: Bitmap + Glyph/Metadata Table.

## D-003: شناسه‌های پایدار

**وضعیت:** پذیرفته‌شده

Asset ID بعد از اختصاص نباید با مرتب‌سازی، حذف یا افزودن فایل‌های دیگر تغییر کند. Builder باید شناسه‌های حذف‌شده را مدیریت کند و از استفاده ناخواسته مجدد جلوگیری کند یا سیاست آن را صریح سازد.

## D-004: جدایی فضای Firmware و Assets

**وضعیت:** پذیرفته‌شده

Firmware و Assets در دو حافظه مستقل قرار دارند. فایل‌های پروگرام جدا می‌مانند، ولی می‌توانند در Container واحد بسته‌بندی شوند.

## D-005: بسته `.w25pack`

**وضعیت:** ایده پذیرفته‌شده، مشخصات باز

محتوای پیشنهادی:

```text
project.w25pack
├── firmware.hex
├── assets.bin
├── manifest.json
├── device.json
└── checksums.json
```

لازم است نسخه قالب، مدل هدف، ظرفیت، الگوریتم CRC، زمان ساخت و سازگاری کتابخانه در Manifest ثبت شود.

## D-006: دو مسیر پروگرام W25Q

**وضعیت:** پذیرفته‌شده

- مسیر A: STM32 واسط از طریق USB/UART و سپس SPI
- مسیر B: CH341A مستقیم از طریق SPI

STM32 واسط برای Update محصول و CH341A برای تولید/تعمیر مناسب‌تر است.

## D-007: Verify با CRC32

**وضعیت:** پذیرفته‌شده

پس از نوشتن، STM32 یا پروگرامر محتوای W25Q را خوانده و CRC32 را محاسبه می‌کند. ارسال فقط CRC به PC نسبت به Read-back کامل سریع‌تر است. در حالت خطا امکان Verify دقیق بلوک معیوب باید وجود داشته باشد.

## D-008: Update تفاضلی

**وضعیت:** هدف نسخه بعد از MVP

CRC هر منبع/سکتور مقایسه و فقط نواحی تغییرکرده پاک و نوشته شود. چیدمان باید محدودیت پاک‌شدن سکتوری را در نظر بگیرد.

## تصمیم‌های باز

| موضوع | گزینه‌های فعلی | معیار انتخاب |
|---|---|---|
| زبان نرم‌افزار ویندوز | C#/.NET، Python، C++/Qt | توسعه‌پذیری، USB، بسته‌بندی، UI |
| پروتکل PC↔STM32 | UART، USB CDC، USB HID | سرعت، درایور، پایداری |
| Firmware واسط | Bootloader دائمی، Firmware موقت | فضای Flash، Update میدانی، بازیابی |
| صوت نهایی | PCM8، PCM16، IMA-ADPCM | کیفیت، حجم، CPU |
| فشرده‌سازی تصویر | خام، RLE، روش بلوکی | سرعت رسم، نسبت فشرده‌سازی |
| Layout حافظه | جدول ابتدای Flash، انتهای Flash، دوکپی | Recovery و Atomic Update |
| CRC | CRC32/ISO-HDLC یا گونه دیگر | سازگاری دقیق PC و STM32 |
| UI Programmer | در Asset Builder یا ابزار سوم | سادگی محصول و نگهداری |
